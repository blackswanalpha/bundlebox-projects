### F9 in detail

Three changes, one per cause:

1. **The yield table moved out of the pipeline** into `src/learn/episodes.js`. A verb typed by hand displaces the same work as the same verb inside a gear; two tables would have disagreed about how much.
2. **`src/cli.js` records one episode per verb**, after dispatch, never throwing and never changing the exit code. Turns are counted by the documented formula — `files_read + commands + searches + floor(rows/40)` — never guessed.
3. **Attribution rewritten**: an episode belongs to a session when it names the same run, or when it falls in the window that *prepared* the session — since the previous session on this workspace ended, capped at 24h. Each episode lands in at most one session.

Repeats claim nothing. Every entry carries a **digest over what the verb produced**, and turns are counted only for an answer not already given — matched on the digest alone, so `bb findings` straight after `bb scan` prints the set `scan` just computed and adds zero. A verb with no digest claims zero rather than a plausible number, and records what it *would* have been worth on the row.

Measured on this session, live, after the fix:

`doctor` reporting 0 is the rule working: it has no digest, so it claims nothing.

### O4 was not a bug

`dead-exports` flagged `FIELDS`, `Invalid`, `validate`, `ROUTES`, `handle` and
`warn` across three files in `demo/src`. Every one was correct: they were
exported and referenced nowhere. The fix belonged in the demo, and the
detector's own hint said which half to take — "delete it, or stop exporting it":

- `Invalid` and `validate` un-exported; `create` and `update` are their only callers, and a second entry into validation is how two callers come to disagree about what an item is.
- `FIELDS` given a job: the server projects every response through it, so a field added to the store does not become a public one by accident. `items.project` is the projection and `server.test.js` asserts the wire shape matches.
- `log.warn` used where a warning is owed — a malformed body and an unknown route, both of which are usually a client bug somebody is about to spend an afternoon on.
- `ROUTES` and `handle` covered by a new `demo/test/server.test.js` that drives the real handler with a recording response. An exported surface with no consumer is one `bb scan` is right to call dead; the answer is a consumer or a deletion, and here it was a test worth having.

A second, smaller one fell out: `demo/package.json` declared `"lint": "node scripts/lint.js"` and the script did not exist. Gate detection would have picked `npm run lint` as the quick gate and it would have failed on every lane. A script a gate detects and cannot run is worse than no script.

Calibration, from the same pass: `uniform-radius` and `shadow-monotony` fired at
8 uses. A 200-line stylesheet with **6** `border-radius` and **5** `box-shadow`
declarations, all identical, is unambiguously monotone and was missed. Both
floors are now 5, and both are config (`designlabs.generic_min`).

O1 — the Windows path bug in `git commit` — turned out to be the first of
nine, all now fixed and merged; CI is green on Windows, macOS and Linux across
Node 20, 22 and 24. The one that mattered most was not O1 at all: `laneEnv`
handed a spawned lane no `PATH`, and the acceptance gate hard-coded `bash`, so
`bb run --apply` had never been able to work on Windows.

Two limitations remain, named in the README rather than left to be found: a
**piped** acceptance gate on Windows reports the last command's exit code
because `cmd.exe` has no `set -o pipefail`, and `bb session` may find no
transcripts there because the projects-directory name is unverified.
